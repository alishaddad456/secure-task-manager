# Security architecture

## Identity and access
- GitHub Actions assumes a dedicated AWS deployment role using OIDC and a repository/branch-constrained trust relationship.
- ECS task execution and application task roles are separate.
- The application security group accepts inbound traffic only from the ALB security group.
- The database security group accepts PostgreSQL only from the application security group.

## Secrets and encryption
- The database password is generated by Terraform and stored in AWS Secrets Manager.
- The secret is encrypted with the project customer-managed KMS key.
- RDS storage is encrypted at rest.
- CloudWatch log groups use the project KMS key.
- The ECR repository and ALB log bucket currently use AES-256 server-side encryption.
- The application database connection is configured for PostgreSQL TLS; the related Checkov transit-encryption finding remains to be verified against the deployed parameter group and client connection settings.

## Network boundaries
- Public ALB is the only intended inbound application entry point.
- ECS tasks use public subnets/public IPs in this cost-conscious deployment, but their inbound security-group rule allows application traffic only from the ALB security group.
- RDS is private and not publicly accessible.
- The public listener currently uses HTTP because an ACM certificate/custom domain has not been configured. Do not use the demo endpoint for sensitive traffic.

## Detection and audit
- VPC Flow Logs capture all VPC traffic and deliver to CloudWatch.
- ALB access logs are delivered to an S3 bucket with public access blocked.
- Application and PostgreSQL logs are exported to CloudWatch.
- CloudWatch alarms cover ECS CPU/memory, ALB 5xx responses, and RDS CPU; an operations dashboard is provisioned.

## Build and release controls
- CI runs pytest with a coverage threshold, Bandit, pip-audit, Docker build/runtime smoke tests, Trivy, Terraform fmt/validate, and Checkov.
- Deployment uses an immutable commit-SHA image tag, one-off database migrations, ECS service stabilization, and a readiness check.
- Checkov currently runs in soft-fail mode. See [the residual-risk register](residual-risk-register.md) for the exact findings from the latest verified run.
